Cross-platform file transfer across macOS, Linux, and Windows

Reviewed against the implementation: October 17, 2026

Cross-platform transfer problems often come from file semantics rather than the network alone. A browser can move a selected file's bytes between macOS, Linux, and Windows, but it does not automatically preserve directory trees, Unix permissions, symbolic links, or a photo library's database. DropItOver provides nearby browser transfers, explicit rooms, and temporary links. This guide explains how to package material deliberately, test delivery, and handle the receiving system's naming and saving behavior. Begin with copies or a harmless fixture so a troubleshooting attempt cannot damage your only source.

Decide what must survive the trip

For ordinary documents, images, and videos, the selected file and its name may be enough. For source code, a project directory can include hidden files, executable bits, symlinks, and case-sensitive names that Windows tools handle differently. Create an archive with a format appropriate to the recipient. A tar archive is useful for Unix metadata when both sides have compatible tools; ZIP is broadly convenient but extraction behavior varies. Do not assume a browser's multiple-file picker represents a recursive directory backup. State the packaging method when handing over a project.

Watch for two files whose names differ only by case, such as Report.txt and report.txt. A case-insensitive destination may not retain both under those names. Characters legal on one operating system may also be rejected or sanitized on another. Test a small representative archive containing your real naming patterns before migrating a large collection. Keep checksums and a source inventory when exact reproduction matters. Transport encryption cannot correct an archive that omitted hidden files or a destination extractor that changed permissions.

Choose the smallest workable transfer route

Use nearby devices for a live exchange on a trusted network. Use a room when you need an explicit URL across different discovery groups. Use an expiring link when the recipient cannot remain online. A room is not a persistent shared folder, and a download link is not version synchronization. Link files pass through Worker-managed encryption and temporary storage, with default two GiB per-file and eight GiB bundle limits. A direct transfer can still face browser resource limits, so do not infer unlimited file size from the absence of cloud storage.

Open the canonical HTTPS site in maintained browsers on both machines. Set clear nicknames and transfer a small fixture first. Archive extraction and permission checks happen after saving

Nearby discovery groups browsers using their public IP at our signaling service. It does not scan mDNS advertisements or mount network shares. A VPN can separate otherwise adjacent machines into different groups. Conversely, a shared public address can group devices that cannot reach each other locally. After the recipient accepts, ICE finds a direct or relay path for encrypted traffic. If discovery works but no file bytes move, inspect firewall, router isolation, and selected candidate-pair state. Changing the device nickname will not repair an unreachable route.

On Windows 11, review the active Public or Private profile and the browser's application permission. On Linux, inspect your distribution's firewall and any container or sandbox network policy. On macOS, check applicable application firewall or organizational rules. Avoid disabling the entire host firewall. A small-file test on a trusted hotspot can isolate the original network. If a managed policy blocks peer traffic, use the approved transfer channel rather than adding broad exceptions. TURN may help only when configured and permitted by that network.

Handle interruption and resource pressure

Keep both tabs foregrounded and prevent system sleep during live delivery. The sender reads slices and uses bufferedAmount backpressure. The receiver groups chunks into Blob parts but retains a representation of the full file for saving. Memory and temporary storage can therefore become the limiting factor, especially when the receiver runs many other applications. A page reload does not preserve a partially received file. Retain the source and restart deliberately instead of assuming the next selection will resume from the interrupted byte.

For a stored link, wait for upload and finalization before handing over the URL. Choose an expiry that fits time-zone differences and the recipient's availability. Download range resumption is not implemented for the encrypted stream, so use a stable connection for large archives. If burn-after-read is enabled, explain that another person may not be able to retrieve the same bundle later. Deleting a link removes the service's stored copy; it cannot remove extracted files from the recipient's machine.

Verify bytes and then verify meaning

Compare the saved archive's byte size and SHA-256 digest with the source, using trusted local command-line tools when available. On Windows, PowerShell Get-FileHash can calculate SHA-256; macOS commonly provides shasum, and Linux commonly provides sha256sum. Check the command's file path carefully and quote names containing spaces. A matching digest confirms the selected archive arrived unchanged. Then extract into a new directory, inspect the inventory and permissions, and run the project's ordinary verification before replacing an existing working copy.

Never extract an untrusted archive blindly over personal files. The transport does not inspect executable content, remove malware, or guarantee that paths inside an archive are safe. For a project handoff, exclude local credentials, private keys, environment files, and unnecessary build artifacts before packaging. This minimizes both transfer size and accidental disclosure. If the goal is ongoing collaboration with history and merges, a version-control workflow may be more appropriate than repeatedly sending full directory archives.

Performance comparisons that can be repeated

Use an identical one GiB fixture and the same archive for every method. Record OS, browser version, CPU, available memory, network arrangement, and direct or relay route. Repeat three trials and report median payload time, connection setup, and saving separately. If comparing Snapdrop, identify the deployment; if comparing LocalSend, identify the installed version. A local browser test and a distant cloud upload measure different paths, so explain that difference alongside the numbers.

When asking support for help, include the failed stage and file size without attaching private archives, credentials, live share links, or raw network diagnostic dumps.
